# Agent instructions

Read [construct.md](construct.md) before editing. Keep all content employer-neutral and reusable. Use the smallest useful change, verify the outcome, update relevant indexes and report uncertainty honestly.

Never copy personal Life Hub notes into this public repository. Exclude health, family, finance, schedule, promotion, performance, interview and employer-confidential information. Exclude internal GitLab links, discussions, screenshots, customer information, unreleased features and private architecture.

These rules apply to files, commit messages, issues, pull requests, logs and attachments. Write generic lessons independently and use synthetic examples. Review them before publication; removing names alone is insufficient.

Scan all proposed files and staged diffs for secrets and private information. Report suspected secrets by path and type without displaying values. Stop publication until findings are resolved. Never add real credentials or import private directories.

Follow the work-to-GitHub synchronisation rules in construct.md. Verify the target remote and branch, reconcile existing changes, inspect the commit and verify the remote after an authorised push. Do not overwrite history or configure automatic mirroring.

Do not add or choose a software licence without an explicit decision. Record skill status from evidence; placeholders are not tested skills. Preserve these boundaries in future changes.
